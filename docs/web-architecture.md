## Web architecture guide

Guide for engineers building features on the `apps/web` foundation (phase 2: collection pages, card detail, deck builder). It covers where things live, how to read and write data, the design system, routing, and testing. All paths are relative to `apps/web/src`.

## Folder map

    app/            Shell and routing: App (providers), AppRoutes, AppShell, Sidebar, TabBar, TopBar,
                    OmniboxSlot, ErrorBoundary, paths.ts (route table), nav.ts, useGlobalShortcuts
    config/         constants.ts - every shared constant (storage keys, limits, sync timing, ids)
    data/           Dexie database, repository helpers, mutations, live hooks, catalog provider, backup
    sync/           Sync engine, HTTP client, config storage, SyncProvider, SyncIndicator
    settings/       settingsStore.ts - typed localStorage preferences (theme, density, default view)
    styles/         tokens.css (design tokens), base.css (reset, .page scaffolding)
    ui/             Design system components, import from ui/index.ts
    features/       One folder per feature area. Phase 2 owns collection/, cards/, decks/.
                    settings/ and PlaceholderPage.tsx are foundation code.
    lib/            Small framework-free helpers (download, formatBytes)
    dev/            Dev-only tools: UiShowcase (route /dev/ui) and make-dev-catalog.mjs
    test/           setup.ts (jsdom, fake-indexeddb, storage shim) and helpers.ts (fake sync server)

## Provider stack

`app/App.tsx` wires, outermost first: root `ErrorBoundary`, settings applier (theme and density on `<html>`), `ToastProvider`, `StorageGate`, `CatalogProvider`, `BrowserRouter` (basename from the Vite base), `SyncProvider`, then `AppRoutes`. Inside a feature page you can call `useToast`, `useCatalog`, `useSync` and every data hook without any setup.

## Reading data

All reads are live queries (dexie-react-hooks). Components re-render when rows change, including writes that arrive from sync. Hooks never return tombstones. **Loading contract:** every hook returns `undefined` until its first read completes, so loading (`undefined`) and genuinely empty (`[]`, or `null` for `useDeck`) are different states. A failed read is logged and stays `undefined` in the hook, but it also flips the shared database health state (`data/health.ts`), and `StorageGate` then replaces the UI with the Storage unavailable screen and a retry; the same happens if the database cannot open, another tab forces a version change, or the connection closes mid-session. Pages therefore need no failure branch. `DataLossNotice` additionally warns once if the browser held data before (a `hadData` marker in syncMeta) and every table is now empty. Write `const owned = useOwned() ?? []` when loading and empty look the same to you.

    import { useOwned, useOwnedForPrinting, useTaggings, useTagCounts,
             useDecks, useRecentDecks, useDeck, useSavedSearches,
             useSearchContext, useRequiredCatalog } from '../../data';

    const owned = useOwned();                       // OwnedEntry[]
    const copies = useOwnedForPrinting(printingKey); // rows for one printing, every finish and condition
    const deck = useDeck(deckId);                   // undefined while loading, null when missing or deleted
    const ctx = useSearchContext();                 // core SearchContext, undefined until loaded, then memoized
    const catalog = useRequiredCatalog();           // Catalog, only beneath <CatalogGate>

`useSearchContext()` returns `{ owned, tagsByCard, decksByCard }` (or `undefined` while loading) from one combined live query, and keeps its identity until data changes, so it is safe in `useMemo` dependency lists. It re-reads the owned table on every write; if that shows up in profiles, derive per-card counts incrementally in a feature hook:

    const results = useMemo(() => (ctx ? runSearch(query, catalog, ctx, { sort }) : undefined), [query, catalog, ctx, sort]);

## The catalog

`CatalogProvider` fetches `/catalog.json`. The service worker precaches it with the app shell, so after the first online visit (and the Ready to work offline toast) it loads with no network; a StaleWhileRevalidate rule is only a fallback when a build shipped without it. Routes that need it sit under `CatalogRoute` in `AppRoutes.tsx`, which renders a skeleton while loading and a retryable error state on failure, so pages under it can call `useRequiredCatalog()` without checking status. Settings sits outside the gate on purpose. `useCatalog()` returns `{ state, retry }` with `state.status` of `loading`, `ready` or `error` for components that must handle every state themselves.

In development, if `/catalog.json` is missing the app falls back to `/dev-catalog.json`, generated by `node apps/web/src/dev/make-dev-catalog.mjs` from `data/raw/cards.json` (gitignored, never built).

## Retired printing keys

The catalog may carry `keyAliases` (retired key to current key). After the catalog loads, `CatalogProvider` runs `migrateRetiredKeys` once per catalog build: owned rows and deck slot pins on retired keys move to the current key in one transaction, quantities that collapse onto the same key are summed, the old rows are tombstoned and everything is re-stamped so sync propagates it. The migration cannot roll back or double a quantity, even when a stale device runs it before pulling: new rows are stamped with the OLD rows' newest `updatedAt` (so they lose to any genuine newer edit), an existing target row is replaced only if the old data is strictly newer (never summed with it), several retired rows collapsing onto one key are summed into byte-identical rows on every device, old rows are tombstoned with a fresh stamp, and rewritten rows go through a sync outbox because their stamps are intentionally old. It waits for the first completed sync of the session when sync is configured. Keys that are neither current nor aliased are never deleted; they are reported in `useCatalog().migration.orphanedKeys` and surfaced once as a warning toast. `resolvePrintingKey(catalog, key)` maps any key, and `/card/<retired key>` redirects to the current key through `CardAliasRedirect`, so feature pages always receive a current key when one exists.

## Writing data

Every write goes through `data/mutations.ts`. Never call `db.table.put` from a feature. The mutations stamp `updatedAt` with the shared clock, write tombstones for deletes, run inside one Dexie transaction, and announce the change so auto sync can react.

    import { setOwnedQuantity, adjustOwnedQuantity, addTag, addTagToCards, removeTag,
             renameTag, deleteTag, setCardTags, saveDeck, duplicateDeck, deleteDeck,
             saveSearch, deleteSearch } from '../../data';

    await setOwnedQuantity({ printingKey, finish: 'foil', condition: 'NM' }, 3); // zero tombstones the row
    await adjustOwnedQuantity({ printingKey }, +1);                              // finish and condition default to normal and NM
    await addTagToCards(selectedCardKeys, 'aggro package');                      // bulk tag
    await renameTag('aggro', 'tempo');                                           // across every card
    const deck = await saveDeck({ name: 'Fury tempo' });                         // no id creates, an id updates
    await saveDeck({ id: deck.id, main: [{ cardKey: 'vi', count: 3 }] });
    await saveSearch({ name: 'Fury units', query: 'fury unit' });                // appears in the sidebar slot

Rules to keep:

- Owned rows have a deterministic id `printingKey|finish|condition`, so two devices adding the same copy converge on one record.
- A tagging record id equals its `cardKey`. Tags keep the user's casing and compare case-insensitively.
- Quantity is clamped to 0..`MAX_OWNED_QUANTITY` (constants.ts). Zero means removed; NaN or Infinity keeps the current value instead of deleting. `Stepper` defaults its max to the same constant.
- Every stamp uses core `nextUpdatedAt`, so a skewed clock cannot make an edit lose to its own previous version. Mutations announce a change only when rows were written.
- `saveDeck` ignores undefined fields, trims or defaults the name, and refuses to overwrite a deleted deck unless you pass `{ revive: true }`.
- Failed writes (quota, blocked transactions) show an error toast, are logged, and rethrow so callers can react. The first successful write asks the browser for persistent storage.
- Backup restore is `restoreBackup(userData)`; export input is `readUserData()`. Restore re-stamps rows and tombstones anything missing from the backup so other devices follow.
- Schema changes: append a new entry to `SCHEMA_VERSIONS` in `data/db.ts` with the full stores map and an optional `upgrade` callback. Never edit a shipped version.

## Sync

`SyncProvider` owns one `SyncEngine`. It syncs on start, every minute, on reconnect, when the tab becomes visible, and 2 seconds after local changes. Components only need the hook:

    const { state, syncNow } = useSync();   // state.status: idle | syncing | error | offline | disabled

Server identity: the engine stores the server URL and `serverId`. A different URL or id, a `resync` flag, or a server clock that moves backwards resets the cursors and runs a full push and pull; Settings has a Resync button. Pulled records are validated with core `validateCollectionRecord` and invalid ones are dropped and counted (`state.rejected`). Records the server returns for ids we just pushed (for example a clamped future `updatedAt`) are applied when not edited since. A resync (or a device that was offline longer than the server tombstone retention) can resurrect rows that were deleted elsewhere in the meantime, because the pruned delete markers no longer exist. Remote copies are not echoed back, and errors back off exponentially with jitter for background triggers.

Protocol: `POST {serverUrl}/sync` with a bearer token, body `SyncRequest`, response `SyncResponse` (types in `@sc/core`). Dirty records are those with `updatedAt` newer than a watermark stored in `syncMeta`; remote changes are merged with core `mergeRecords` in one transaction. URL and token live in localStorage only and are never logged or placed in error messages. Timing constants are in `config/constants.ts` (`SYNC`). The engine is tested against an in-memory fake server in `test/helpers.ts`.

## Routing and shell conventions

- Route patterns and link builders live in `app/paths.ts`. Use `paths.card(printingKey)`, `paths.deck(id)`, `paths.collection(query)`; never hand write URLs.
- Routes: `/collection` (default), `/sets`, `/decks`, `/decks/:deckId`, `/card/:printingKey`, `/settings`. Add a route by adding a lazy page in `AppRoutes.tsx`.
- Pages are default exports, lazy loaded behind Suspense and an error boundary that resets on navigation. A page should render a `<div className="page">` root with a `PageHeader`; the shell provides the scroll container (`main`), safe-area padding, sidebar and tab bar.
- The omnibox contract: the top bar renders `OmniboxSlot`. Its input must keep `id={OMNIBOX_INPUT_ID}` so the `/` shortcut focuses it, and submitting navigates to `/collection?q=...` (`QUERY_PARAM`). The collection page reads the `q` search param as the single source of truth for the query. Replace the body of `OmniboxSlot.tsx` freely (suggestions, arrow key results) but keep both contracts. Call `focusOmnibox()` from any page to focus it programmatically.
- Saved searches render in the sidebar as links to `/collection?q=<query>`; recent decks link to `/decks/:id`. Both come from the data hooks, no extra wiring.

The five stand-ins are `features/collection/CollectionPage.tsx`, `features/collection/SetsPage.tsx`, `features/cards/CardDetailPage.tsx`, `features/decks/DecksPage.tsx` and `features/decks/DeckBuilderPage.tsx`. ## Design system

Import everything from `ui/index.ts`. Components use CSS variables from `styles/tokens.css` only; never use raw colors or pixel sizes in feature CSS.

Tokens: surfaces (`--bg-app`, `--bg-surface`, `--bg-raised`, `--bg-overlay`), text (`--text`, `--text-muted`, `--text-faint`), `--border`, accent (`--accent`, `--accent-soft`, `--accent-text`, `--on-accent`), status (`--success`, `--warning`, `--danger`, `--info`, each with `-soft`), domains (`--domain-fury` and friends), rarity (`--rarity-common` through `--rarity-promo`), spacing (`--space-1` to `--space-8`), radius, type scale (`--text-xs` to `--text-3xl`), elevation (`--shadow-1` to `--shadow-3`), motion (`--dur-fast`, `--dur`, `--ease-out`), layout and safe-area variables. Dark is the default; `data-theme="light"` and `data-density="compact"` on `<html>` switch variants, and reduced motion zeroes the duration tokens.

Components:

- Actions: `Button` (primary, secondary, ghost, danger; sizes; `icon`, `loading`), `IconButton` (requires `label`), `Menu`, `Popover`, `Tooltip`.
- Forms: `TextField`, `SearchField` (`onValueChange`, `onSearch`, Esc clears), `Select`, `Checkbox`, `Switch`, `SegmentedControl`, `Stepper` (quantity).
- Display: `DomainGlyph` (original geometric marks per domain, used inside `DomainBadge`), `Badge`, `Chip` (toggle or removable), `DomainBadge`, `RarityBadge`, `ProgressBar`, `Tabs`, `Skeleton`, `Spinner`, `EmptyState`, `ErrorState`, `PageHeader`, `Icon` (typed `IconName`; add an icon by adding one entry in `ui/Icon.tsx`).
- Overlays: `Dialog`, `Drawer` (bottom sheet on phones, or left and right), `ToastProvider` with `useToast().show({ title, tone, action })`.
- Cards: `CardImage` (744:1039, lazy, skeleton, offline fallback, `foil`), `CardTile` (art, rarity glow, domain dots, owned badge, optional `to` link or `onClick` toggle, `footer` slot for a Stepper).

Open `/dev/ui` in the dev server to see every component, in both themes. Preferences come from `useSettings()` (`theme`, `density`, `defaultView`, `sidebarCollapsed`); use `defaultView` as the initial collection layout.

## Shell resilience

The tree is wrapped in a root `ErrorBoundary` (reload screen, raw errors only logged) and `StorageGate`, which opens IndexedDB before rendering and explains private mode, blocked storage or a full disk with a retry. Pages sit inside a per-route boundary. Dialogs and drawers capture the opener before the app root goes inert and restore focus after it is released (falling back to the main landmark if the opener left the DOM). Toasts use two always-mounted live regions (polite, and assertive for errors), pause on hover or focus, and never auto-dismiss errors or toasts with actions. While a Dialog or Drawer is open the app root is inert and the `/` shortcut is ignored.

## Accessibility baseline

Semantic landmarks (`header`, `nav`, `main`, `aside`), a skip link, visible focus rings via `:focus-visible`, labelled controls, `aria-live` for toasts and the stepper, focus trap and restore in `Dialog` and `Drawer`, and keyboard support in `Menu`, `Tabs` and `SegmentedControl`. Control borders use `--control-border` (3:1), focus rings keep a transparent outline so they survive forced-colors mode, and controls are at least 44px on touch or narrow screens (`--control-h-*`). Keep new components to the same bar: every icon-only control needs a label, color is never the only signal, and animations must respect `prefers-reduced-motion` (use the motion tokens).

## PWA

`vite.config.ts` configures vite-plugin-pwa with prompt-based updates (`app/UpdatePrompt.tsx` shows a Reload toast), a precached shell, CacheFirst with expiration for card art from `cmsassets.rgpub.io` (opaque responses allowed, capped entries), and StaleWhileRevalidate for `/catalog.json`. Icons: PNG 192, 512, maskable and apple-touch generated by `src/dev/make-icons.mjs` (built-ins only), plus SVG. The catalog is precached for first-session offline use; card art is cached opaque (the CDN sends no CORS headers) with a 300 entry cap and purge on quota errors. Set `SC_BASE=/subpath/` for a subpath deploy (manifest, router and service worker follow it) and `SC_BUILD_TIME` or `SOURCE_DATE_EPOCH` for reproducible builds. Open tabs check for a new service worker hourly. Settings offers "Clear card art". The service worker is disabled under vitest.

## Testing conventions

- Run `npx vitest run` inside `apps/web`, and `npx tsc -p apps/web/tsconfig.json` from the repo root. `npm run build -w @sc/web` must also pass. `styles/contrast.test.ts` fails if a token pair drops below WCAG AA in either theme, and `styles/breakpoints.test.ts` keeps CSS media queries aligned with `DESKTOP_MIN_WIDTH_REM`.
- Tests sit beside the code as `*.test.ts` or `*.test.tsx`. Use Testing Library queries by role and label, and `userEvent`.
- IndexedDB is `fake-indexeddb`; call `resetDb()` from `test/helpers.ts` in `beforeEach`. Use `installFakeClock()` when asserting `updatedAt`.
- Core is implemented but still evolving: prefer injecting dependencies, and use `lwwMerge` and the in-memory `createFakeSyncServer()` from `test/helpers.ts` instead of relying on core internals.
- Wrap page tests with `ToastProvider`, `CatalogProvider load={async () => fixture}`, `MemoryRouter` and `SyncProvider autoStart={false}`; see `app/shell.test.tsx` for a full example.
- `localStorage` is an in-memory shim installed in `test/setup.ts` because recent Node versions ship a conflicting global.
